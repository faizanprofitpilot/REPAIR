# REPAIR — Submission (~200 words)

REPAIR converts a real agentic failure into a machine-enforced runtime policy. A support agent issues a Stripe TEST refund through One; a controlled `CommitThenDisconnect` fault hides success and the agent retries. Without policy, that uncorrelated replay double-refunds. CrewAI Flow diagnoses the failure, You.com researches first-party recovery semantics, and a constrained DSL synthesizes candidates. Daytona (or a labeled local harness) deterministically rejects an overbroad rule and promotes a narrowed domain-free policy. The same Python gateway then blocks an identical Linear replay, verifies state by `REPAIR_OP_ID`, and prevents a duplicate issue before One is called. V1 and V3 share model, prompt, tools, fault, and starting state—only the promoted policy differs. MEMORY becomes POLICY; advice becomes enforcement.
